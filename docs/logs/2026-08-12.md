### 3.1 InputBox 剪贴板契约（src/input_box.ts，33 行）

`InputBox extends TextareaRenderable`，覆写 `handleKeyPress`（判定顺序）：

1. `traits.suspend === true` → 直接委托 super（对齐上游挂起语义，index.bun.js:8384）。
2. `key.ctrl && !meta && !super && !hyper && hasSelection()`：
   - `name === "c"` → `(this.ctx as CliRenderer).copyToClipboardOSC52(getSelectedText())`
     → return true（选区保留）。
   - `name === "x"` → 复制**成功才** `deleteSelection()`；失败保选区；两种情况都
     return true（不让 super 看到，防 main.ts 的 ctrl+x→delete 绑定误删）。
3. 其余（含无选区）→ `super.handleKeyPress(key)`。

关键 API 事实（已核验，档案完整版见 systems/opentui-inputbox.md）：

- RenderContext **无剪贴板字段**（types.d.ts:93-141）；`ctx.clipboard` 双重不合法
  （字段不存在 + CliRenderer.clipboard 是 private，renderer.d.ts:297）。正确路径
  `(this.ctx as CliRenderer).copyToClipboardOSC52(text)`（renderer.d.ts:538）。
- `copyToClipboardOSC52` 内部自带 isOsc52Supported 门控，不支持时静默 return false；
  **返回 true 仅表示输出路径被调用，不保证终端接受**。Windows Terminal 支持 OSC52
  写入（微软 PR #5823，v1.4/v1.5+）[外部查证]，不支持读回。
- 粘贴零改动：bracketed paste 由 core 原生处理（focus 自动接线 pasteHandler →
  TextareaRenderable.handlePaste → insertText）。
- `deleteSelection()` 内部已清选区（chunk-bun-8fkgaxc6.js:5862-5868 → 5836-5840），
  勿重复调 ctx.clearSelection。
