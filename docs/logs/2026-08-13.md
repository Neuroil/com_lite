## 3. EVP 学习过程记录（作者初稿，待润色）

今日主任务是加密算法，实际耗时大头在 OpenSSL EVP API 的学习上：

- **EVP API 学习曲线陡**：花大量时间读 API 文档与官方 GitHub 示例代码
  （openssl/openssl 仓库的 demos / 示例），对比官方推荐写法与旧版 EVP_* 单函数
  风格差异（一次一哈希 vs 上下文复用、参数反复传入 vs EVP_MD_CTX 打包）。
- **C 风格资源释放**：示例大量使用 `goto cleanUp`/`goto err` 统一收尾（`EVP_MD_CTX_free` /
  `OPENSSL_free` 等），与 Linux 内核的 `goto out` 错误处理模式一脉相承——
  相对熟悉这种写法，但阅读起来仍然困难：成功路径与错误路径交错、标签跳跃
  破坏线性阅读，需要逐标签追踪资源是否已释放。
- 学习结论沉淀方向：`hash_details.h` 的 `security::details` 命名空间承接
  EVP 封装，对外只暴露 `security::salt_hash_compute` 的简洁签名。

## 5. 审查发现的问题

### 5.1 gen_salt 死循环 bug（已修复）

```cpp
int success = 0;
while (success) {
    success = RAND_bytes(...);
}
```

`success` 初值 0 → 循环体**永不执行**，产出全零盐。审查后已改为
`do { ... } while (success != 1)`（RAND_bytes 成功返回 1，失败 0 / -1），
并补注释说明返回值语义。

### 5.2 魔数 host 字节序（跨架构隐患，记录）

encoder 以 `memcpy` host 序写魔数，decoder 同序读回——同机自洽，测试注释也
明写"本机（小端）"；但 body_len 走 `htonl` 大端而 magic 不走，跨字节序
机器间不兼容。当前单机学习阶段可接受，若未来跨端部署需对 magic 统一字节序。

### 5.3 小项

- `decoder.h` 魔数比较用 `magic_num ^ types::magic_head`（XOR 判不等），
  语义正确但可读性差——**已改为 `!=`**。
- `security.h` 未直接 include `<vector>` / `<string>` / `<utility>`（`std::forward`），
  目前靠 openssl 头间接引入——**已补齐显式 include**（含 `<cstddef>`）。
- `salt_hash_compute` 参数名 `hex` 实为待哈希内容，命名待定稿。
